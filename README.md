# CNDL_chat+

> Клиентский чат-менеджер Fabric для Minecraft 1.21.11, 26.2 и 26.3.

## Коротко о моде

CNDL_chat+ работает на любом multiplayer-сервере с корректным адресом. Серверная часть не нужна.
F8 открывает менеджер чата на вкладке «Друзья».
F9 и автоматизация принадлежат CNDL_toolkit.

Мод умеет:

- хранить историю и не удаляемые автоматически закладки отдельно для каждого адреса;
- разделять чат на встроенные и редактируемые вкладки, добавлять время, поиск и объединение повторов;
- скрывать слова, игроков и Discord-сообщения, показывать Chat Alerts;
- хранить друзей, показывать HUD и выполнять проверку статуса;
- ограничивать количество друзей в HUD и отключать интерфейс брака;
- предлагать или автоматически принимать запросы телепорта;
- выполнять команды Vanilla-box через меню, F7 и `\`; меню Alt+ПКМ позволяет переводить деньги и исключать игрока из привата;
- получать профиль игрока через VnbxBridge на Minecraft 26.2/26.3 или через серверный lookup.

В одиночной игре, при некорректном адресе или повреждённой инициализированной конфигурации серверные
функции не активируются. На всех серверах применяется одна фиксированная конфигурация Vanilla-box.

## Быстрый старт

1. Установите Fabric Loader 0.19.5 или новее для Minecraft 1.21.11, 26.2 либо 26.3.
2. Установите Fabric API для своей версии игры.
3. Скачайте подходящий JAR из [GitHub Releases](https://github.com/gasada-dev/CNDL_chat-plus/releases/latest).
4. Поместите JAR в `.minecraft/mods`.
5. Подключитесь к multiplayer-серверу и нажмите F8.

| Minecraft | Fabric API |
| --- | --- |
| 1.21.11 | `0.141.6+1.21.11` или новее |
| 26.2 | `0.156.0+26.2` или новее |
| 26.3 | `0.161.0+26.3` или новее |

## Граница multiplayer

Принимается любой корректный multiplayer address: hostname, IPv4 или IPv6 с допустимым optional
port. Регистр hostname и конечные точки нормализуются. Мод не делает DNS-проверок. Отклоняются
malformed-адреса, недопустимые порты и singleplayer.

История и закладки используют нормализованный адрес только как ключ хранения. Этот
адрес не выбирает конфигурацию: всегда используется одна конфигурация Vanilla-box.

## Конфигурация и миграция

Единственный источник серверных настроек:

```text
.minecraft/config/server-templates/vanilla-box.json
```

В нём хранятся каналы, фильтры, друзья, команды, парсеры и политика телепорта. Встроенного JSON,
скрытого fallback и выбора другого шаблона нет. Java-фабрики команд и парсеров задают значения
только при первой инициализации, они не заменяют существующий файл.

`cndl-chat-plus.json` остаётся глобальным и совместимым представлением. Он хранит настройки
интерфейса, истории, HUD, звуков и inert automation bridge. Поля `enabled`, `rules`,
`periodicMessages`, reply prefixes и связанные legacy-значения не исполняются CNDL_chat+, но
сохраняются для миграции CNDL_toolkit. Nullable `storageVersion` отсутствует, равен `null` или `0`
до миграции. После успешного завершения записывается `1` последним.

При первом переходе старые активные server-support данные сначала побайтово проверяются в архиве:

```text
.minecraft/config/cndl-chat-plus-retired-server-support-v1/
  manifest.json
  files/<relative-path>
```

`manifest.json` содержит отсортированные `path`, `size` и SHA-256. Архив неизменяем, допускает
безопасное продолжение после прерывания и проверяется до удаления оригиналов. После проверки
удаляются только `server-templates.json`, JSON из `server-templates/` кроме `vanilla-box.json`,
и файлы из `cndl-chat-plus-template-imports/`. Архив не имеет UI восстановления.

`cndl-chat-plus.legacy-backup.json`, branded-источники, включая
`gasada-chat-responder-template-imports/`, история и закладки остаются на месте. Branded imports
больше не копируются в активный путь. Если migration не завершилась или при `storageVersion: 1`
нет корректного `vanilla-box.json`, мод остаётся inactive.

Подробности: [конфигурация](docs/CONFIG.md), [архитектура](docs/ARCHITECTURE.md),
[команды](docs/SERVER_COMMANDS.md), [ручные проверки](docs/MANUAL_TESTS.md).

## Отсутствующие возможности

В моде больше нет экранов шаблонов, редактора, импорта, каталога, выбора, копирования,
привязки, default-конфигурации или настроек команд и парсеров для другого сервера. Команды и
парсеры Vanilla-box не редактируются через UI.

## Сборка из исходников

Нужен JDK 25. Gradle устанавливать отдельно не нужно.

```bash
./gradlew test
./gradlew build
```

Готовые JAR появляются в `build/release/`. Процедура выпуска описана в
[docs/RELEASE.md](docs/RELEASE.md).
