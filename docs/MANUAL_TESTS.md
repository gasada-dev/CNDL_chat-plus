# Ручные проверки CNDL_chat+

Сценарии предназначены для проверки текущего поведения. Используйте тестовый сервер/аккаунт: команды `/pay`, `/mail send` и `/ignoreplayer` изменяют серверное состояние.

Для migration проверки сначала запустите CNDL_chat+ 0.8.0 с существующим config, затем
установите приватный [CNDL_toolkit 0.1.0](https://github.com/gasada-dev/CNDL_toolkit/releases/tag/v0.1.0).
F8 открывает менеджер чата, F9 — toolkit. CNDL_chat+ не должен показывать или исполнять automation.

Перед проверкой сохраните копию `.minecraft/config/cndl-chat-plus.json`. Для timing-сценариев не меняйте системное время во время запуска.

## 1. Запуск, F8 и сохранение

1. Запустить Minecraft 26.2 с Fabric и модом.
2. В главном меню нажать F8: не должно быть crash; если экран не открывается вне мира, повторить после входа на сервер.
3. На сервере нажать F8.
4. Проверить две равные вкладки: «Чёрный список» и «Друзья»; первым открыт «Чёрный список».
5. Нажать «?» в левом верхнем углу, пройти все страницы и вернуться назад.
6. Открыть «Настройки» и вернуться назад.
7. Изменить безопасное поле, закрыть и открыть экран.

Ожидается: экран не ставит игру на паузу; F8 открывает `ResponderScreen`; сохранённое значение восстанавливается после перезапуска.

### 1.1. Глобальные настройки

1. Открыть F8 → «Настройки».
2. По очереди переключить вкладки чата, поиск, время сообщений, объединение повторов,
   меню сообщений по ПКМ, чат Discord, HUD друзей и оба звука.
3. Сменить active template и сервер, снова открыть настройки.
4. Нажать «Настройка команд для сервера».

Ожидается: все переключатели сохраняют значения для всех серверов; отключение одного не
меняет остальные. Кнопка открывает экран серверных шаблонов.

### 1.2. Серверные шаблоны

1. Открыть «Настройки», переключить active template через список серверов, затем нажать
   «Настройка команд для сервера».
2. Создать empty template, copy Vanilla-box и copy выбранного; переименовать draft и задать exact/wildcard patterns.
3. Проверить временный выбор, default и permanent binding текущего address после reconnect.
4. Убедиться, что active/default/единственный template нельзя удалить; для обычного delete требуется второе нажатие.
5. Настроить разные channel/friend/filter в двух templates и переключаться между ними.

Ожидается: настройки не смешиваются, старые lookup/notices не переносятся, неизвестный сервер без default не получает чужой template.

### 1.3. Готовые и внешние шаблоны

1. На чистом config запустить мод и проверить bundled `Vanilla-box` и `Vanilla-game` с доменами `mc.vanilla-box.ru` и `mc.vanilla-game.ru`. У `vanilla-game` должны быть пустые друзья и last seen.
2. Изменить его команду, перезапустить клиент и убедиться, что bundled catalog не перезаписал изменение.
3. Положить корректный template JSON в `.minecraft/config/cndl-chat-plus-template-imports/`.
4. На экране шаблонов нажать «Загрузить шаблоны из папки» и проверить новую запись.
5. Повторить с duplicate ID, invalid path-like ID, неверным placeholder/regex и файлом >1 MiB.

Ожидается: valid template добавлен без автоматической активации; duplicate пропущен;
invalid files не меняют root/существующие templates и показывают ошибку.

### 1.4. Миграция game и информация об игроке

1. На копии schema 1 с ID `game` проверить переход в `vanilla-game`, сохранение данных,
   default и exact bindings. Повторный запуск ничего не меняет.
2. Отдельно создать оба ID: после запуска оба файла и их данные должны сохраниться,
   а log должен содержать предупреждение о конфликте.
3. На `mc.vanilla-game.ru` открыть F8: кнопка `Информация об игроке` должна находиться
   непосредственно над вкладкой `Друзья`.
4. Ввести начало ника, выбрать online suggestion и убедиться, что сеть не используется
   до нажатия `Обновить`.
5. Обновить профиль: проверить online, клан, супруга, регистрацию, последний вход,
   доступные контакты и постройки. Строк `Строительство: ... очков` и `Контакты: скрыты`
   быть не должно.
6. Проверить ошибку API и lookup fallback: клан, ранг, статус и другие строки `/clan lookup`
   должны появиться в разделе «Данные сервера», но не в обычном чате.
7. В editor template открыть «Инфо игрока», изменить regex с capture group 1 под другой
   сервер и повторить lookup.
8. Проверить disconnect/switch во время запроса: устаревшие данные не должны появиться на
   новом сервере.
9. Выбрать на VanillaGame игрока, у которого API возвращает пустой брак, но запись есть в
   `/marry list`. Проверить последовательные страницы, появление строки `Супруг` и
   отсутствие вывода служебного списка в обычном чате.
10. В editor `Vanilla-game` изменить `Список браков — {page}` и три marriage regex. В
    `Vanilla-box` и других templates эти поля отсутствуют, `/marry list` не отправляется.

### 1.5. Импорт настроек

1. Открыть «Импорт настроек», выбрать разные source/target.
2. Выбрать часть categories и поочерёдно REPLACE/MERGE/SKIP.
3. Создать preview и до confirmation проверить, что оба файла не изменились.
4. Подтвердить импорт, проверить только target; source должен совпадать с backup.
5. Проверить case-insensitive dedup и last seen overwrite toggle; categories rules/periodic отсутствуют.
6. Вручную создать invalid command/parser в source и убедиться, что apply заблокирован.

Ожидается: import любой оставшейся категории не меняет target `responderEnabled`, `rules`,
reply prefixes и `periodicMessages`; source остаётся неизменным.

## 2. Каналы

1. Открыть «Настройки» → «Настройка команд для сервера» → редактор нужного шаблона →
   «Каналы» и настроить global prefix и
   global/clan/private markers.
2. Получить сообщения каждого канала и проверить вкладки, unread counters и context actions.
3. Отправить строку одновременно с private и clan/global markers: private имеет приоритет,
   clan имеет приоритет над global.
4. Проверить Discord marker: сообщение попадает в отдельную Discord-вкладку.

Ожидается: настройки влияют только на классификацию/фильтрацию. CNDL_chat+ не отправляет reply.

## 3. Word filter

1. Добавить `реклама` и проверить сообщения `РЕКЛАМА`, `это реклама здесь`.
2. Добавить `казино*`, `*казино`, `*казино*` по одному и проверить соответствующие фразы.
3. Добавить Unicode phrase, например `привет мир`, и проверить регистр.
4. Удалить элементы через UI.

Ожидается: pattern без `*` ищется как substring без учёта регистра; pattern с `*` использует glob внутри текста; скрытое сообщение не попадает в историю/вкладки; blank item нельзя добавить через UI.

## 4. Discord filter и мут

1. Получить сообщения форматов `[Discord] name » text`, `(Discord) name ...` и вариантов `< >`, `{ }`, `« »`, `‹ ›`, `〈 〉`.
2. В F8 открыть «Настройки» и выключить «Чат Discord».
3. Включить обратно, добавить sender в «Мут Discord» и повторить.
4. Снять локальный мут.

Ожидается: общий toggle скрывает все распознанные Discord messages; локальный мут скрывает только совпавшего sender без учёта регистра.

## 5. Серверный `/ignoreplayer`

1. В blacklist/nicks выбрать suggestion или ввести valid player name.
2. Нажать «Мут» на тестовом сервере.
3. Повторить с пробелом, `/`, Unicode name и длиной >16.

Ожидается: valid name отправляет ровно `/ignoreplayer <name>`; invalid input показывает ошибку и ничего не отправляет.

## 6. Друзья и suggestions

1. Ввести prefix online player; проверить sorted suggestions и Tab completion.
2. Добавить valid friend, выбрать его, закрыть/открыть screen.
3. Попытаться добавить duplicate с другим регистром и invalid name.
4. Удалить friend.
5. Внизу справа переключить автоприём между «Выкл», «От всех», «От друзей» и
   «От выбранных друзей». Персональная кнопка должна появляться только в последнем режиме
   после выбора друга и сохраняться после повторного открытия F8.

Ожидается: duplicate/invalid отклоняются; friend сохраняется; удаление также удаляет его
`friendLastSeen` и персональный автоприём; own player отсутствует в suggestions.

## 7. Friend lookup

1. Добавить не менее шести друзей, подключиться и не открывать F8 первые 30 секунд.
2. Проверить автоматическую отправку `/clan lookup <friend>` в сохранённом порядке; отдельно
   переподключиться и открыть friends tab раньше 30 секунд, чтобы запустить тот же единственный обход сразу.
3. После пяти завершённых lookup убедиться, что шестой начинается только после паузы около 60 секунд.
4. Проверить ответы с `Был в сети:`, `Был онлайн:`, `Неактивен:` и завершающей строкой `Тип убийства:`.
5. Проверить вариант, где точное время отсутствует и используется `Неактивен`.
6. Имитировать lookup без ответа: после timeout около 15 секунд тот же друг должен повториться
   один раз после 60-секундной паузы, затем очередь должна продолжиться.
7. Отключиться во время очереди и подключиться снова.
8. Вне фоновой проверки вручную отправить `/clan lookup <player>`.

Ожидается: служебный блок фоновой проверки скрыт; ответ на ручную команду виден в чате;
точное last-seen имеет приоритет, к inactive при необходимости добавляется `назад`; результат
виден у друга и сохраняется; очередь очищается при disconnect; внутри группы следующий запрос
не раньше 10 секунд, после пятого действует пауза 60 секунд, timeout около 15 секунд.

Регрессионная проверка риска: вне активного lookup получить обычное сообщение, содержащее одно из широких слов `статус:`, `клан:` или `KDR:`. Зафиксировать, скрывает ли его текущая версия; не менять это поведение внутри несвязанного PR.

## 8. Online state, HUD и уведомление

1. Включить HUD и звук появления друга в глобальных настройках, затем подключиться,
   когда friend уже online.
2. В течение первых 30 секунд убедиться в отсутствии ложного sound/notice.
3. После warmup friend должен быть offline непрерывно не менее 5 секунд, затем появиться online.
4. Проверить одно notice `<friend> в сети!` примерно на 4 секунды и один звук `PLAYER_LEVELUP` с текущими pitch/volume.
5. Выключить HUD, оставив звук включённым; повторить переход друга offline → online.
6. Включить HUD, выключить звук и повторить переход.

Ожидается: список online отображается справа снизу; initial online friend не вызывает notice;
короткий TAB-list flicker <5 секунд не вызывает notice; HUD и звук работают независимо.

## 9. Действия с другом

Перед проверкой открыть настройки выбранного шаблона → «Команды» и по очереди заменить
`w` на `msg`, `call` на `tpa`, `ignoreplayer` на тестовые эквиваленты сервера. Сохранить,
переключиться на другой template и убедиться, что его команды не изменились. На странице
«Discord» задать marker regex без слова `discord` и проверить распознавание формата сервера.

Навести курсор на кнопки ЛС, почты, денег и телепорта. Каждая подсказка должна показывать
развёрнутую команду активного шаблона (`{player}` → `ник`, `{message}` → `сообщение`,
`{amount}` → `сумма`); после переключения шаблона подсказки должны обновиться.

На тестовом сервере выбрать друга и проверить отдельно:

- ЛС: non-empty text → `/w <friend> <text>`, затем очищается только поле ЛС.
- Почта: non-empty independent text → `/mail send <friend> <text>`, очищается только mail field.
- Деньги: `10`, `10.25`, `10,25` принимаются; `-1`, `1e3`, `1.234`, text отклоняются; серверное действие подтверждать осторожно.
- ТП: button → `/call <friend>`.

Без выбранного друга или без connection ни одна команда не отправляется и показывается ошибка.

### 9.1. Alt+ПКМ по игроку Vanilla-box

1. Активировать точный template `vanilla-box`, навести прицел на игрока в обычной дальности и
   нажать `Alt+ПКМ`.
2. Проверить меню с ником hit target и четырьмя пунктами.
3. Поочерёдно проверить `/ps add <ник>`, `/ps remove <ник>`, `/vm trusted add <ник>` и
   `/vm trusted remove <ник>`.
4. Повторить без Alt, по не-player entity, вне дальности и на другом active template.
5. Открыть меню, сменить connection/template и нажать действие: команда не должна отправиться.

Ожидается: только `Alt+ПКМ` по player entity на Vanilla-box отменяет обычный ПКМ. Каждое
действие отправляет ровно одну валидированную команду; остальные случаи сохраняют vanilla behavior.

## 10. Принятие запроса телепорта

1. На Vanilla-box или Vanilla-game получить запрос вида `Player просит телепортироваться к вам.`.
2. Проверить однократный обычный голос шалкера, HUD-кнопку `Принять ТП от Player (60)` и уменьшающийся счётчик.
3. Открыть чат, нажать кнопку и проверить отправку `/tpaccept` и исчезновение кнопки.
4. Получить новый запрос и не нажимать кнопку: через 60 секунд она исчезает.
5. Повторить с disconnect и сменой template: старый запрос исчезает.
6. Очистить `acceptTeleport` или `teleportRequestPattern`: кнопка не появляется.
7. Проверить режимы: «Выкл» всегда оставляет ручную кнопку; «От всех» принимает любой запрос;
   «От друзей» принимает только ники из active friends; «От выбранных друзей» — только отмеченные.
8. Для автопринятого запроса проверить единственную отправку `/tpaccept`, отсутствие HUD-кнопки
   и звука. При ошибке отправки должна остаться ручная кнопка.
9. Выключить глобальный «Звук входящего ТП»: ручная кнопка должна остаться, звук отсутствовать.

Ожидается: команда берётся из active template; без connection, команды или parser pattern
ничего не отправляется. Несовпавшая ручная кнопка видна во время обычной игры, для клика требуется открыть чат.

## 11. Проверка обновления

1. Заполнить `UPDATE_NOTES.md`, опубликовать тестовый latest GitHub Release с numeric tag
   `vX.Y.Z` и обоими target JAR, затем запустить более старую сборку.
2. Убедиться, что в main menu/connection screen окно не появляется.
3. Войти на сервер и дождаться освобождения GUI.
4. Проверить увеличенное окно: оно показывает текст `UPDATE_NOTES.md`, а длинный остаток
   заменяется `...` без перекрытия кнопок.
5. Нажать «Посмотреть все изменения»: после `ConfirmLinkScreen` должен открыться
   `UPDATE_NOTES.md` точного тега. Отменить открытие.
6. Нажать обе кнопки «Скачать» и проверить `ConfirmLinkScreen`, затем отменить.
7. Повторить с равной/старой version, tag без numeric version, отсутствующим/неверным asset, redirect, неверным Content-Type/UTF-8, body >4 KiB, HTTP URL, user info, fragment/query и другим host/repository.
8. Запустить без сети.

Ожидается: проверка один раз за запуск, async; показывается только valid newer update; URL не открывается без confirmation; invalid/network failure не мешают работе мода.

## 12. Повреждённый config

1. При закрытом клиенте сделать backup config.
2. Записать синтаксически неверный JSON.
3. Запустить клиент и проверить log.
4. Не открывая UI, завершить клиент и проверить исходный файл.
5. Повторить, открыть и закрыть F8 screen, затем проверить файл.
6. Восстановить backup вручную.

Ожидается: migration/load error логируется, runtime получает defaults, а `cndl-chat-plus.legacy-backup.json` сохраняет исходные повреждённые bytes, потому что backup создаётся до parse. После закрытия `ResponderScreen` основной файл может быть перезаписан defaults; восстановление выполняется из backup вручную.

## 13. Старый config и sanitize

1. Оставить только старые `gasada-chat-responder.json`, imports и chat-history directories.
2. Запустить мод и проверить появление соответствующих `cndl-chat-plus-*` файлов.
3. Убедиться, что старые файлы сохранены, bytes совпадают и существующие новые файлы не заменены.

Проверить отдельными копиями JSON:

- null visible collections/wrappers;
- blank/null/duplicate entries с разным регистром;
- `globalMarkers` без `(!)`;
- пять periodic slots с interval `0`, отрицательными и `Integer.MAX_VALUE`;
- null `rules`/`periodicMessages` и null nested rule/message values;
- legacy `periodicEnabled`/`periodicMessage`/`periodicIntervalMinutes` одновременно со списком;
- точную старую пару default rules.

Ожидается: visible fields sanitizes по `docs/CONFIG.md`; все automation values, order/count,
invalid intervals, nulls и singleton сохраняются без изменений в compatible JSON. При initial
migration non-empty list переносится вместо singleton; при пустом/null list и заданном
`periodicEnabled` singleton создаёт одну template entry, не меняя source JSON.

## 14. История чата

1. Зайти на сервер с `chatHistoryEnabled: true`, написать/получить >100 сообщений (спам ботом или долгая сессия).
2. Прокрутить чат вверх: доступны больше 100 сообщений, до `chatHistoryLimit`.
3. Выйти с сервера и зайти снова: прежние сообщения видны сразу, до новых.
4. Проверить `config/cndl-chat-plus-chat-history/<server>.json` — файл появился, JSON валиден, нет `.tmp`.
5. Повредить JSON вручную и зайти: клиент не падает, в log warn, история просто пустая.
6. Установить `chatHistoryPersist: false` — после перезахода история не восстанавливается.
7. Установить `chatHistoryEnabled: false` — лимит чата снова vanilla 100, файлы не пишутся.
8. Зайти в singleplayer: файлы истории не создаются.

Ожидается: лимит чата поднимается mixin'ом на обоих target'ах (1.21.11 и 26.2);
если mixin молча не применился (require=0), лимит остаётся 100 — это сигнал перепроверить
байткод после обновления Minecraft.

## 15. Вкладки чата и timestamps

1. Зайти на сервер: у каждого нового сообщения серый префикс `[HH:mm]` с реальным временем.
2. Открыть чат (T): над верхней строкой чата видна панель
   `Все Глобал Локал Клан ЛС Discord Система`; над панелью на месте будущего search box
   видна серая подсказка `Ctrl+F - поиск`;
   подсказки команд их не перекрывают.
3. Попросить отправить сообщения в глобал (`!`), локал, ЛС, клан: у соответствующих вкладок
   растут красные счётчики, пока вкладка не активна. Если сервер шлёт чат системными пакетами,
   сообщения с маркерами (`!`, `[лс]`, `(клан)`) всё равно попадают в свои вкладки, а не в
   `Система`; в `Система` — только сообщения без маркеров (join/leave, broadcast).
4. Кликнуть вкладку `Глобал`: остаются только сообщения с `(!)`/`!`; счётчик вкладки сброшен;
   вкладка подсвечена рамкой.
5. Кликнуть `ЛС`, `Клан`, `Система` (join/leave, server broadcast), `Discord`, `Все` —
   фильтрация соответствует каналу; `Все` показывает всё.
6. Закрыть чат, получить сообщения, открыть снова: счётчики накопились, активная вкладка
   сохранилась.
7. Выйти/зайти на сервер: счётчики и каналы сброшены; восстановленная история имеет префикс
   с исходным временем (не двойной).
8. `"chatTabsEnabled": false` → панель не рисуется, фильтрация выключена.
9. `"chatTimestampsEnabled": false` → префиксов нет, вкладки работают.
10. Проверить, что скрытое фильтром сообщение не попадает ни во вкладки, ни в счётчики.
11. Те же переключатели изменить через F8 → «Настройки» и проверить после смены сервера.

Ожидается: фильтр и панель работают на обоих target'ах; require=0 молча отключает фичу при
смене байткода — после обновления Minecraft перепроверить этот сценарий первым.

### 15.1. Поиск по чату

1. Открыть чат и нажать Ctrl+F: над вкладками появляется строка `Поиск по чату` с фокусом.
2. Ввести часть сообщения в другом регистре: остаются только совпадения без учёта регистра.
3. Выбрать вкладку: видны только сообщения, одновременно подходящие вкладке и запросу.
4. Очистить запрос: возвращаются все сообщения active tab.
5. Снова ввести запрос и нажать Esc: поиск скрывается, input чата получает фокус, чат остаётся открыт.
6. Нажать Esc вне поиска: чат закрывается. Открыть снова и убедиться, что старый запрос сброшен.
7. Проверить `"chatSearchEnabled": false`: Ctrl+F не перехватывается модом, фильтрации нет.

Ожидается: поиск не меняет unread counters, не теряет сообщения из истории и работает на обоих target'ах.

### 15.2. Контекстное меню сообщения

1. Нажать ПКМ по global/local/clan/private сообщению с валидным Minecraft-ником: меню открывается у курсора.
2. Проверить порядок `Копировать ник` → `Копировать сообщение`, draft ЛС, pay и mail; команды берутся из active template,
   draft появляется в input и не отправляется автоматически.
3. С Chat Heads проверить, что synthetic фрагмент `[Ник head]` не попадает в copied message и не ломает ник.
4. На тестовом игроке проверить add friend, ignore, `Запрос на ТП` и открытие предзаполненной информации.
5. Нажать ПКМ по Discord-сообщению: доступны только copy Discord-имени и сообщения.
6. Нажать ПКМ по join/broadcast без sender: доступно только copy сообщения.
7. Очистить active template: командные действия исчезают, скрытый Vanilla-box fallback не появляется.
8. Проверить ЛКМ вне меню, Esc и повторный ПКМ: меню закрывается, ссылки/вкладки под открытым меню
   не активируются.
9. Повторить при chat scale и line spacing не по умолчанию, после scroll, на wrapped сообщении,
   во вкладке и с active search.
10. Проверить `"chatContextMenuEnabled": false`: ПКМ обрабатывается vanilla, меню мода не появляется.

Ожидается: выбирается именно строка под курсором; unavailable/invalid command templates не показываются,
содержимое сообщения и ник не попадают в log.

### 15.3. Повторы сообщений

1. Получить три полностью одинаковых player chat сообщения подряд: должна остаться одна строка `x3`.
2. Получить `A`, `B`, `A`: должны остаться три строки без счётчика.
3. Повторить с одинаковыми system/broadcast сообщениями и убедиться, что player/system серии не смешиваются.
4. Проверить, что timestamp строки меняется на время последнего повтора, а unread растёт только один раз.
5. Переподключиться: collapsed строка должна восстановиться одной history entry без двойного timestamp.
6. Повторить для wrapped сообщения, active tab/search и контекстного меню.
7. Получить два одинаковых запроса ТП: строка объединяется, но timeout/кнопка/политика обрабатывают оба события.
8. Выключить «Объединять повторы»: одинаковые сообщения должны снова отображаться отдельно.

Ожидается: объединяются только непосредственно соседние строки с тем же видимым текстом,
форматированием и source type;
любая другая строка завершает серию, overlay и скрытые фильтром сообщения в неё не входят.

### 15.4. Chat Alerts

1. В F8 → «Настройки» → `Chat Alerts` создать TEXT rule `gasada`, канал «Любой», HUD и звук.
2. Получить `Gasada` в другом регистре: проверить одно HUD-уведомление и один vanilla sound на каждое входящее сообщение.
3. Создать PRIVATE-only rule: global message не срабатывает, ЛС срабатывает.
4. Отдельно проверить маску `*продам*алмазы*` и Unicode/case-insensitive regex.
5. Ввести invalid regex и пустой pattern: экран остаётся открыт, правило не сохраняется, видна ошибка.
6. Одним сообщением активировать несколько rules с HUD/звуком: виден один notice и слышен один sound.
7. Проверить muted player, muted word, выключенный Discord и служебный lookup block: alerts отсутствуют.
8. Получить серию одинаковых сообщений: duplicate collapse работает как раньше, alert получает каждое событие.
9. Переподключиться с persisted history: восстановленные сообщения не вызывают HUD/sound.
10. Выключить global `Chat Alerts`: rules остаются после reopen/restart, но не срабатывают.
11. Переключить server template: rules сохраняются глобально, новые сообщения используют каналы нового template.
12. Повторить минимум TEXT/HUD/sound/invalid-regex/reconnect на Minecraft 1.21.11 и 26.2.
13. Создать правило по нику sender: ник до `»`/`→` не вызывает alert, то же слово в теле сообщения вызывает.

### 15.5. Закладки сообщений

1. ПКМ по player message → `Сохранить в закладки`; нажать `Закладки` над вкладками открытого чата.

5. Сохранить Discord и system/broadcast без sender.
6. С Chat Heads и timestamps убедиться, что `[Ник head]` и synthetic `[HH:mm]` не входят в text.
7. Сохранить wrapped message при изменённых chat scale/line spacing/scroll, active tab и search: создаётся одна запись целого target.
8. Отключить `chatHistoryEnabled` и `chatHistoryPersist`: bookmark переживает reconnect на том же multiplayer server.
